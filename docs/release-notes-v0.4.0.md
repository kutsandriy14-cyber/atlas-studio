# Orvexa Studio v0.4.0

**Orvexa Studio v0.4.0** — обновление IDE для разработки плагинов Orvexa Code. Выпуск убирает ручное перечисление файлов проекта, добавляет локальное тестирование `.atp`-пакета и не позволяет отправить изменённый проект в каталог без успешной проверки.

| Направление | Что изменилось |
|---|---|
| Автопоиск файлов | Studio рекурсивно находит `.atlas` и ресурсы проекта в стабильном порядке. |
| Исключения | Каталоги `build`, `dist`, VCS и скрытые каталоги не попадают в пакет. Пути архива нормализуются и проверяются. |
| Автоматическая сборка | Кнопка сборки компилирует исходники, упаковывает ресурсы и сохраняет актуальный список файлов в `atlas-project.json`. |
| StudioTestRunner | Появился офлайн-тестовый pipeline: compile, ATBC validation, package build, временный sandbox и очистка. |
| Test UI | Добавлены кнопка «Тест» и вкладка тестового лога с диагностикой результата. |
| Publish gate | Публикация блокируется, если текущий проект не прошёл тестирование после последнего изменения. |
| Асинхронность | Тестирование запускается через QtConcurrent и возвращает результат в UI через watcher. |
| Версия | IDE, консольный компилятор, updater User-Agent и Windows CI обновлены до `0.4.0`. |

## Автоматическая сборка проекта

Studio больше не требует вручную поддерживать список исходных и ресурсных файлов. При сохранении и сборке проект сканируется рекурсивно, а результат записывается в совместимый `atlas-project.json`. Порядок файлов детерминирован, поэтому повторная сборка не создаёт случайных изменений.

В пакет включаются только разрешённые файлы проекта. Исключаются каталоги сборки и распространения, репозитории систем контроля версий и скрытые каталоги. Archive paths проходят нормализацию и проверку на выход за корень проекта.

## Локальное тестирование плагина

`StudioTestRunner` выполняет офлайн-проверку по одному пользовательскому действию:

1. сканирует проект и проверяет структуру;
2. компилирует найденные `.atlas`-исходники;
3. декодирует и валидирует байт-код ATBC 2;
4. собирает `.atp` в указанный путь;
5. создаёт временный sandbox для проверки пакета;
6. возвращает диагностические сообщения и удаляет временную среду.

Результат отображается на вкладке **Тестовый лог**. При ошибке Studio показывает конкретные диагностические сообщения и не сохраняет неуспешный результат как разрешение на публикацию.

| Результат | Поведение Studio |
|---|---|
| Успех | Кнопка публикации разрешена; путь последнего проверенного пакета сохраняется до изменения проекта. |
| Ошибка компиляции | Публикация остаётся заблокированной; в логе показывается диагностика. |
| Ошибка ATBC или упаковки | Публикация остаётся заблокированной; временная среда очищается. |
| Изменение проекта | `m_lastTestPassed` сбрасывается, поэтому требуется повторный тест. |

## Публикация в каталог

Путь отправки в `atlas-plugin-submissions` теперь требует успешного тестирования именно текущего состояния проекта. Простого наличия ранее собранного `.atp` недостаточно: любое изменение, влияющее на проект, инвалидирует test gate.

Это предотвращает публикацию пакета, который отличается от последней проверенной версии исходников. Обязательные файлы публикации и требования непроверенного каталога Launcher остаются действующими.

## Проверка выпуска

Studio CTest проходит **5 из 5** тестов после добавления тестовой вкладки и кнопки. UI smoke test проверяет три нижние вкладки, наличие действия тестирования и сохранение корректной структуры окна.

> Внутренние имена `atlas::`, `.atlas` и `atlas-project.json` сохранены для совместимости. Пользовательские названия IDE, компилятора и релизных артефактов используют Orvexa.

## Известные ограничения

Полноценная интерактивная отладка с breakpoint, пошаговым выполнением, просмотром стека и остановкой долгого сценария остаётся отдельной задачей. Текущий тестовый стенд предназначен для локальной офлайн-проверки сборки и упаковки до отправки в каталог.

## История
