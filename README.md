# Orvexa Studio

**Orvexa Studio** — отдельная программа на C++17 и Qt 5.15 для создания расширений Orvexa Code для Orvexa Launcher. Она не является частью процесса установки Minecraft и не требует установленного компилятора C++ у автора готового расширения. Программа создаёт проект, редактирует метаданные и Orvexa Code, компилирует его в **ATBC 2** и собирает устанавливаемый пакет `.atp`.

> ATBC 2 — это бинарный формат данных Orvexa Runtime, а не DLL и не машинный код. Готовый `.atp` может содержать несколько объявленных программ `*.atbc` и статические ресурсы; исходные файлы `*.atlas` в архив не копируются. Бинарный формат не следует рассматривать как средство защиты интеллектуальной собственности: его назначение — воспроизводимая доставка ограниченной программы и проверка её целостности.

| Компонент | Назначение | Результат |
|---|---|---|
| `OrvexaStudio.exe` | Визуальная IDE: создание проекта, форма метаданных, редактор и упаковка | `build/main.atbc` и `dist/<id>-<version>.atp` |
| `OrvexaCompiler.exe` | Консольная компиляция одного `.atlas` с явными метаданными | Один файл ATBC 2 |
| `OrvexaUpdater.exe` | Отдельная проверка, загрузка и безопасное применение обновления Studio | Обновлённая папка установки после закрытия IDE |
| `atlas_studio_services` | Общая библиотека компилятора, упаковщика и проверки обновлений | Используется программами Studio и Updater |

## Что умеет Orvexa Studio 0.1.0

IDE создаёт и открывает проекты Orvexa Code, сохраняет метаданные плагина и исходный код, отображает диагностику с номерами строк и выполняет бинарную компиляцию. Форма проекта содержит ID, название, версию, автора, описание, категорию, минимальную версию Launcher, сайт, разрешения, декларации страниц UI и декларации действий Runtime.

Раздел **«Страницы UI»** является белым списком ID вкладок, которые программа может создать через `ui.page.create`. Раздел **«Действия Runtime»** задаёт белый список действий доверенных модулей Runtime, на которые Orvexa Code вправе ссылаться. Поля принимают уникальные ID через запятую; для страниц доступно не более 16 значений, для действий — не более 64. Это устраняет ситуацию, когда синтаксически корректный скрипт пытается создать незадекларированную вкладку и отклоняется Runtime.

| Ограничение | Значение |
|---|---:|
| Исходный файл Orvexa Code | До 128 КиБ |
| Скомпилированный ATBC 2 | До 256 КиБ |
| Команд на событие | До 64 |
| Страниц UI в пакете | До 16 |
| Действий Runtime в пакете | До 64 |
| Разрешённые permissions | `servers.control`, `servers.console`, `files.plugin-data`, `network.metadata` |

## Быстрый старт в IDE

Запустите `OrvexaStudio.exe`, выберите **Файл → Новый проект…** и укажите каталог проекта. Studio создаст каталоги `src`, `build` и `dist`, запишет `atlas-project.json` и готовый стартовый `src/main.atlas`. Стартовый пример уже содержит `welcome` в поле **«Страницы UI»**, поэтому его вызов `ui.page.create id=welcome` согласован с манифестом пакета.

Заполните обязательные поля, внесите изменения в код и нажмите **«Собрать .atp»**. IDE сначала сохранит проект, скомпилирует каждую строку `*.atlas` из поля **«Файлы пакета»** в отдельный `*.atbc`, проверит целостность и сформирует пакет в каталоге `dist`. Установите результат из Orvexa Launcher через **Плагины → Установить .atp**, включите расширение и перезапустите Launcher.

```atlas
on launcher.started
  call ui.page.create id=welcome title="Hello Orvexa"
  call ui.control.add id=welcome type=label text="Плагин создан в Orvexa Studio"
end
```

## Структура проекта

```text
my-plugin/
├── atlas-project.json
├── src/
│   ├── main.atlas
│   └── game-events.atlas
├── assets/
│   └── labels.json
├── build/
│   ├── main.atbc
│   └── game-events.atbc
└── dist/
    └── org.example.my-plugin-1.0.0.atp
```

`atlas-project.json` — редактируемый файл проекта. IDE автоматически создаёт и обновляет его. Поля `pages` и `actions` должны соответствовать вызовам программ. В поле **«Файлы пакета»** каждая непустая строка имеет вид `путь-в-проекте -> путь-в-atp`. Исходник `*.atlas` компилируется в указанную цель `program/*.atbc`; другие разрешённые файлы копируются как статические ресурсы. Строка `src/main.atlas -> program/main.atbc` обязательна и остаётся точкой входа для старых версий Launcher. При упаковке в `.atp` записываются только нормализованный `manifest.json`, скомпилированные `*.atbc` и явно объявленные ресурсы.

| Пример строки | Результат |
|---|---|
| `src/main.atlas -> program/main.atbc` | Главная программа Runtime; обязательна |
| `src/game-events.atlas -> program/game-events.atbc` | Вторая программа, исполняемая на тех же поддерживаемых событиях |
| `assets/labels.json -> resources/labels.json` | Статический ресурс, доступный только как объявленный файл пакета |

Пути должны быть относительными, уникальными и не могут выходить за каталог проекта. Studio отвергает `..`, абсолютные пути, DLL, JAR, EXE, архивы и исходные `*.atlas` в готовом пакете. Совокупно действует лимит **64 МиБ архива, 256 МиБ после распаковки и 256 файлов**.

```json
{
  "formatVersion": 1,
  "id": "org.example.my-plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "publisher": "Example Author",
  "description": "Example Orvexa Code extension.",
  "minimumLauncherVersion": "0.4.0",
  "permissions": ["files.plugin-data"],
  "source": "src/main.atlas",
  "entryPoint": "program/main.atbc",
  "packageFiles": [
    {"source": "src/main.atlas", "destination": "program/main.atbc"},
    {"source": "src/game-events.atlas", "destination": "program/game-events.atbc"},
    {"source": "assets/labels.json", "destination": "resources/labels.json"}
  ],
  "pages": ["welcome"],
  "actions": []
}
```

## OrvexaCompiler

`OrvexaCompiler.exe` удобен для автоматизированной сборки ATBC 2. Он не создаёт `.atp`: упаковка и генерация `manifest.json` выполняются Orvexa Studio либо OrvexaPackager из комплекта Launcher. Все метаданные передаются явно, а компилятор записывает их в ATBC для последующей проверки согласованности.

```text
OrvexaCompiler.exe \
  --id org.example.my-plugin \
  --name "My Plugin" \
  --version 1.0.0 \
  --publisher "Example Author" \
  --description "Example Orvexa Code extension" \
  --permissions files.plugin-data \
  --min-launcher 0.4.0 \
  src\main.atlas build\main.atbc
```

| Параметр | Обязателен | Описание |
|---|---:|---|
| `--id` | Да | ID: строчные латинские буквы, цифры, точки и дефисы; от 3 до 128 символов |
| `--name` | Да | Отображаемое название программы |
| `--version` | Да | Версия в формате SemVer, например `1.0.0` |
| `--publisher` | Да | Автор или издатель |
| `--description` | Да | Краткое назначение расширения |
| `--permissions` | Нет | Список разрешений через запятую |
| `--min-launcher` | Да | Минимальная версия Orvexa Launcher в SemVer |
| `input.atlas` | Да | Исходный файл Orvexa Code |
| `output.atbc` | Да | Путь целевого бинарного ATBC 2 |

## Автообновление

При обычном запуске `OrvexaStudio.exe` через 1,25 секунды запускает отдельный процесс проверки обновлений. Он обращается только к публичному API GitHub Releases репозитория `kutsandriy14-cyber/atlas-studio`, поэтому программе не нужен и не передаётся токен GitHub. Сетевые ошибки не блокируют IDE и не выводят навязчивые диалоги.

Если опубликована более новая стабильная версия, предлагаются три действия: **«Обновить»**, **«Позже»** и **«Игнорировать эту версию»**. Выбранный для игнорирования номер записывается локально в `updater.ini` в каталоге настроек приложения. Для диагностики автопроверку можно отключить параметром запуска `--no-update-check`.

Перед установкой Updater скачивает `SHA256SUMS.txt`, сверяет SHA-256 загружаемого ZIP, запускает временную копию самого себя, ожидает завершения Studio и только затем заменяет файлы. Распаковка выполняется встроенной miniz: она отклоняет абсолютные и выходящие за папку пути, дубликаты, зашифрованные записи, более 4096 записей и распаковку свыше 1 ГиБ. Внешний `7za.exe` не требуется.

Для совместимости с автообновлением каждый стабильный GitHub Release должен содержать ровно один актив, имя которого заканчивается на `-win64-portable.zip`, и `SHA256SUMS.txt` с соответствующей строкой вида `64-символьный-sha256  имя-архива.zip`.

## Граница безопасности

Orvexa Code намеренно не предоставляет доступ к C++, DLL, памяти процесса, командной строке, произвольным путям, произвольной сети или Qt-указателям. Программа реагирует только на поддерживаемые события (`launcher.started`, `game.started`, `game.exited`) и направляет вызовы через ABI-шлюзы Orvexa Runtime. Окончательное решение о разрешениях принимает Orvexa Launcher во время установки и исполнения; метаданные ATBC не повышают полномочия пакета.

> Не помещайте в проект или `.atp` пароли, токены CurseForge, ключи API, JAR-файлы или DLL. Orvexa Code-пакет schema 2 не предназначен для нативных модулей.

## Сборка из исходников

Для нативной сборки необходимы CMake 3.16+, C++17 и Qt 5.15 с компонентами Core, Gui, Network, Widgets и Test.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

После сборки получаются `OrvexaStudio`, `OrvexaCompiler` и `OrvexaUpdater`. В Windows непрерывная интеграция собирает те же исполняемые файлы с Qt 5.15.2 / MinGW 8.1, выполняет CTest, упаковывает переносимый ZIP с Qt Network и публикует SHA-256 как артефакты задания.

## Совместимость

Orvexa Studio 0.1.0 создаёт пакеты **schema 2** для Orvexa Launcher 0.4.0 и новее. Однопрограммные пакеты совместимы с Launcher 0.4.0; пакеты с несколькими `programs` или `resources` требуют Launcher с поддержкой многофайловой schema 2. Пакеты native-qt с DLL используют отдельный `schemaVersion: 1` путь и не создаются этой IDE.
